# בקרת איכות לפני דיווח

עודכן: 2026-10-19. הקובץ נבנה עם הפרויקט: כל פקודה, מסך או נתון הדגמה שנקבעים נכתבים כאן.

## 1. הבדיקה המלאה
(הפקודות שמריצים לפני כל קומיט, ומה צריך לראות בפלט. למשל:)

| מה | פקודה | מה צריך לראות |
|---|---|---|
| טיפוסים | `npm run typecheck` | 0 שגיאות |
| בדיקות | `npm test` | N מתוך N עברו |
| בנייה | `npm run build` | הסתיימה בלי שגיאות |
| הכול יחד | `npm run check` | שלושתם |

- קוראים את מספרי ההצלחה והכישלון בעיניים. לא מחברים את הבדיקות בשרשרת לקומיט.

## 2. בדיקה שנכשלת בלי התיקון
- לכל באג: בדיקה שמשחזרת אותו. מריצים פעם אחת בלי התיקון (נכשלת) ופעם אחת איתו (עוברת).

## 3. מסכים
- כל מסך שהשתנה נפתח בדפדפן ברוחב מחשב (1280) וברוחב טלפון (390).
- בודקים: מצב ריק, מצב טעינה, שגיאה, טקסט ארוך, עברית מימין לשמאל.
- הדשבורד: `npm run dev` ואז http://localhost:3000/oshermax/. לפני דיווח, גם את הבנייה הסטטית: `npm run build && npm run preview` ואז http://localhost:4173/oshermax/, בלי שגיאות בקונסול.
- **עם הכניסה, השמות והקישורים** (כמו בשרת): `npx tsx scripts/build-data.ts --demo --ids-out <tmp>/ids.json`, מעתיקים את `public/data/leads.json` ל-`<tmp>/leads.json`, יוצרים `<tmp>/auth.json` עם סיסמת בדיקה (גיבוב PBKDF2, סיסמה חדשה לכל בדיקה, לא הסיסמה של המנהל), ומריצים `OSHER_PRIVATE_DIR=<tmp> PHP_CLI_SERVER_WORKERS=6 php -S 127.0.0.1:8090 -t <site>` כש-`<site>/oshermax` מצביע על `out`.
- **מדידות לפני דיווח על עיצוב:** בלי גלילה לצד (1280 ו-375), גובה הדף כשהכול סגור ביחידות של מסך (375 על 667: עד 6), ש"מה הבוט הביא" נגמר בתוך המסך הראשון, והיחס בין המספר הראשי לגדול שבשאר המספרים (לפחות 2). גם כשהכול פתוח: בלי גלילה לצד.

## 4. נתוני הדגמה
- עובדים ומצלמים רק על נתוני הדגמה. אף פעם לא על חשבון של לקוח אמיתי.
- `npm run data:demo` יוצר `public/data/leads.json` מומצא (900 לידים, מוצרים בשם Demo). בלעדיו הדף המקומי מציג שגיאת טעינה.

## 5. סביבה חיה
- בסביבה חיה רק קוראים: לוגים, מסכי ניהול, נתונים. לא כותבים ולא מריצים סקריפטים שמשנים.
- אחרי פריסה: מוודאים שהפריסה הצליחה לפני שמבקשים מהמנהל לבדוק.
- שינוי במצב `data` של `static-deploy.sh` נבדק גם הוא מקומית: נתונים לפני שהדשבורד באוויר, עדכון תקין, קובץ שבור, קובץ ריק, ו-`oshermax` של מישהו אחר.
- שינוי ב-`deploy/static-deploy.sh` נבדק קודם מקומית, בתיקיית בית מדומה (`HOME=<tmp>`) עם אתר מדומה שיש בו עוד פרויקטים, בשבעה מקרים: פריסה ראשונה, פריסה חוזרת, בנייה בלי index.html, גרסה לא תואמת, `oshermax` של מישהו אחר, `oshermax` שהוא קישור, ואתר שלא קיים. בכל מקרה בודקים ששאר הפרויקטים באתר לא השתנו.

- שינוי ב-`refresh.php`: מריצים אותו מקומית עם `php -S` וטבלה מדומה (`OSHER_SHEET_URL`), במקרים: רענון תקין, לחיצה חוזרת, עמודה חסרה, גוגל מחזיר דף, טבלה לא זמינה, חמש לחיצות במקביל.

## 5א. מספרים על הגיליון האמיתי
- שינוי שנוגע לחישובים: דוחפים ענף `check/<משהו>` ("פרופיל טבלה" רץ בו בלי פריסה). כל הלשוניות יורדות פעם אחת, וכל הבדיקות רצות על אותו רגע.
- "לפני ואחרי": בענף הבדיקה מוסיפים שלב שמריץ את `check-numbers.ts` ו-`summary.ts` גם על קומיט הבסיס (`git worktree`), על אותם קבצים, ומשווה (ראו `check/27-numbers`).
- קוראים את התוצאה מההערות: `gh api repos/<repo>/check-runs/<job>/annotations`. ההערות ציבוריות: רק ספירות ושמות של קטגוריות.

## 6. חומר עזר לדיווח
- צילומי מסך על נתוני הדגמה, עם `pos.py evidence <issue> <files>`.
- כשלא השתנה שום דבר חזותי: פלט הבדיקות, שורת לוג, או מדידה.
- בדיווח כותבים מה נבדק ואיך, ומה לא נבדק.
