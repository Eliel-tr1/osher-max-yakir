## מלכודות שכדאי לדעת
- הכתובת בלי לוכסן בסוף (/oshermax) עוברת הפניה דרך http ואז ל-https, כמו כל התיקיות באתר. זה עובד, אבל משתפים תמיד את הכתובת עם הלוכסן: https://ai.vitrue.co.il/oshermax/
- באתר ai.vitrue.co.il יש פרויקטים חיים אחרים (בשורש: מחשבון ה-ROI). כל שינוי בפריסה נבדק קודם מקומית, ראו project-qa.
- בשרת, ב-`.bashrc` של המשתמש, שורה 13 שבורה ("umask 007export"). כל חיבור מדפיס שגיאה, והפקודה שהייתה אמורה לרוץ בשורה הזו לא רצה. זה לא קשור לדשבורד.
- הנתונים מגיעים מ-`data/leads.json`, שמתעדכן בלחיצה על כפתור הרענון (בשרת, PHP), או בפריסת קוד (TypeScript). שתי הגרסאות חייבות להישאר זהות: `tests/parity.test.ts`.
- הסוכן לא יכול להפעיל workflow ידנית. "עדכון נתונים" רץ גם כשמשנים את `.github/run-refresh`.
- לפני פריסה ראשונה לשרת: להראות למנהל מה "בדיקת שרת" מצאה, ולקבל אישור שזה השרת הנכון.
- הלוג המלא של Actions לא נגיש מסביבת הסוכן. "בדיקת שרת" כותבת את התוצאה כהערה (annotation), ואותה קוראים: `gh api repos/<repo>/check-runs/<job>/annotations`.
- הסוכן לא יכול להפעיל workflow ידנית. "בדיקת שרת" רצה כשהקובץ שלה משתנה, ו"בדיקות לסוכן השיחות" כשמשתנה `.github/run-agent-probe`.
- בסביבת הענן של הסוכן, `gh` עובד רק דרך REST על הריפו הזה (בלי GraphQL). הצמדת issue ופרויקט GitHub עובדים רק מהמחשב של המנהל או מהממשק.
